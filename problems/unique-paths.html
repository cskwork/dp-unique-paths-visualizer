Dynamic Programming · Grid Pattern

Unique Paths

A robot stands in the top-left corner of a grid. It can only move right or down. How many distinct paths reach the bottom-right corner?

dp[row][col] = dp[row-1][col] + dp[row][col-1]

Every cell is the sum of the cell above it and the cell to its left.

See it build

m = 3, n = 7 → 28 distinct paths to E.

The Problem

One robot, two moves

The grid is m rows by n columns. The robot starts at S and must reach E using only two moves: right, or down. Every cell along the way is reachable by some number of distinct routes, and that count is what we're solving for.

S start E end → move right ↓ move down

First row

Only reachable by moving right, again and again. Every cell here is reachable exactly one way.

First column

Only reachable by moving down, again and again. Every cell here is reachable exactly one way too.

The Key Idea

Every interior cell has exactly two doors in

To stand on any interior cell, the robot's last step was either a move down from the cell above, or a move right from the cell to the left. There is no third way in, so the number of paths to a cell is just the paths from above, plus the paths from the left.

The Code

Same idea, two implementations

The 1D version drops the full grid and keeps only one row alive, overwriting it in place as it scans left to right.

Same time complexity, far less memory: only one row needs to stay alive at any point.

    

  


  

    

      
Pattern To Remember

      

        
Whenever a cell depends only on its top and left neighbors, you're looking at grid DP.

        
dp[row][col] = something(top) + something(left)

        
Same shape shows up in Minimum Path Sum, Unique Paths II, Triangle, and a good chunk of edit-distance-style problems.
